# 디자인 개선 요청 — 주택 매수 의사결정 시뮬레이터

> 작성 2026-08-16 · 대상 `https://hyfin.duckdns.org/hyrealty/`
> 이 문서는 **디자이너에게 건네는 브리프**입니다. 개선안을 받기 위한 재료이지 지시가 아닙니다.

---

## 1. 이 도구가 무엇인가

부부 두 사람이 **실제로 집을 살지 말지** 정하려고 만든 계산기입니다. 가상의 사용자가 아니라
작성자 본인들이 씁니다. 대상 지역은 **창원 · 부산 · 경기** 세 곳으로 고정돼 있고 넓힐 계획이 없습니다.

기존 부동산 계산기와 다른 점은 하나입니다. 보통은 대출과 물건을 따로 계산하는데, 이 둘은 얽혀 있습니다.

```
경기권    = 수도권   → LTV 70%  (생애최초 우대 무효)
창원·부산 = 비수도권 → LTV 80%  (생애최초 우대 유효)
```

**지역을 고르는 순간 대출 조건이 정해집니다.** 이 커플링을 한 화면에서 보이게 하는 것이 존재 이유입니다.

데이터는 국토교통부 실거래가 **44만 건**(2016~2026, 15개 시군구)을 빌드 시점에 구워 넣은
스냅샷입니다. 런타임 API 호출이 없습니다.

---

## 2. 무엇을 결정하려고 보는가

사용자가 이 도구 앞에서 던지는 질문은 다섯 개입니다.

| 질문 | 지금 답하는 화면 |
|---|---|
| 우리 조건으로 **얼마까지** 살 수 있나 | 4단계 가격 나침반 |
| **어떤 대출**이 되고 무엇이 막나 | 4단계 매트릭스 |
| 사는 게 나은가 **빌리는 게** 나은가 | 5단계 매수·전세·월세 |
| 이 단지는 **실제로** 얼마나 올랐나 | 6단계 실거래 수익률 |
| **오른 것들의 공통점**은 뭔가 | 사이드 드로어 |

결정의 성격이 중요합니다. 이건 **한 번 보고 끝나는 대시보드가 아니라**, 두 사람이 몇 주에 걸쳐
가정을 바꿔가며 다시 열어보는 도구입니다. "지금 답이 뭐냐"보다 **"이 답이 어느 가정에 매달려
있느냐"**가 더 중요합니다.

---

## 3. 바꿀 수 없는 제약

디자인 이전에 정해진 것들입니다. 여기에 어긋나는 안은 채택할 수 없습니다.

- **외부 요청 0건의 단일 HTML.** CSS·JS·데이터가 전부 인라인. 웹폰트·아이콘 CDN·이미지 호스팅 불가.
  현재 2.9MB (gzip 854KB). 오프라인·파일 직접 열기로도 동작해야 합니다.
- **한국어 전용.** 다국어 계획 없음.
- **다크 테마 단일.** 라이트 모드 없음.
- **인쇄 가능해야 함.** 논의 자리에 종이로 들고 갑니다 (`print-plain` / `no-print` 클래스 존재).
- 엔진(계산)과 UI가 분리돼 있습니다. **계산 결과의 의미를 바꾸는 제안은 불가**, 표현 방식은 전부 열려 있습니다.

### 설계 원칙 (양보 불가)

1. **점수를 하나로 합치지 않는다.** 입지 88점 + 대출 적합 60점 = 74점은 무의미합니다. 축별로 봅니다.
2. **부정적 결과를 숨기지 않는다.** "자금 부족", "상품별 탈락 사유"가 가장 중요한 정보입니다.
3. **가정값과 실측값을 시각적으로 구분한다.** 지금 실측인 건 전세가율·전월세전환율·실거래가뿐이고,
   투자수익률·상승률·수선유지비는 여전히 자리표시자입니다.
4. **한계를 결과 옆에 붙인다.** 표본이 얇으면 얇다고, 예측이 아니면 아니라고 같은 화면에서 말합니다.

## 4. 지금의 구조

**7개 탭 + 우측 사이드 드로어 1개.** 전부 동렬입니다.

```
1 가구 프로필   2 시나리오   3 물건·입지   4 비교 매트릭스
5 매수·전세·월세   6 실거래 수익률   7 리포트        [→ 수익률 공통점 드로어]
```

화면 규모 (TSX 라인 수): 매트릭스 659 · 3-way 462 · 드로어 452 · 실거래 399 · 물건 391 ·
리포트 224 · 나침반 222 · 프로필 216 · 시나리오 151 · 버블 138.

공용 컴포넌트는 `Card / Badge / Field / Stat / Select / Toggle / SegmentedControl / Button` 정도로
얇습니다. 색은 Tailwind slate 계열 + sky(강조) / emerald(좋음) / amber(주의) / rose(나쁨).

## 5. 관찰된 실패 사례 ← **이 문서에서 가장 중요한 부분**

아래는 추측이 아니라 **실제 사용 중 사용자가 막힌 기록**입니다. 개발 과정에서 사용자가 화면을
보며 직접 물은 것들이고, 전부 고쳤지만 **같은 종류의 실패가 다른 화면에 남아 있을 가능성**이 큽니다.

### ① "초기 투입과 주식 초기 투입의 차이가 뭐야?"

3-way 화면에 두 줄이 나란히 있었습니다.

```
초기 투입        7,000만
주식 초기 투입        0원
적립투자 누계     7,184만   ← 투자가 0인데 적립이 7천만?
```

**원인:** 둘 다 "투입"이라는 말을 쓰면서 실제로는 *같은 목돈이 갈라지는 두 갈래*였습니다.
목돈(계약 시점)과 매달(기간 중)이 시간축으로 분리되지 않아 모순처럼 읽혔습니다.

**조치:** ① 목돈을 어디에 두나 → ② N년 동안 매달 → ③ N년 뒤 손에 남는 것, 3단계로 재구성.
용어도 "주거에 묶임 / 투자에 남김 / 투자에 추가 적립"으로 교체.

### ② "왜 은행 주담대랑 신생아 특례밖에 안 나와? 디딤돌·보금자리론은 반영이 안 된 거야?"

매트릭스 셀이 **승자 상품 하나만** 보여줬습니다. 실제로는 4개 상품이 전부 계산되고 있었고,
보금자리론은 *자격이 되는데 목적함수(월납 최소화)에서 밀린 것*이었습니다.

**원인:** "룰셋에 없다 / 자격이 안 된다 / 목적함수에 밀렸다" 셋이 화면에서 구분되지 않음.
**세 경우의 대응 행동이 완전히 다릅니다** — 각각 개발 요청 / 물건 변경 / 토글 한 번.

**조치:** 셀에 `보금자리론 밀림` `2종 부적격` 배지 추가 + 호버 설명.

### ③ "최고·최저·하위 25%, 안전마진을 종합적으로 봐도 이해가 안 간다"

진입시점 분포가 이렇게 나왔습니다.

```
3년 보유   데이터 기간이 짧아 낼 수 없습니다
5년 보유   중위 4.2%  하위25% 4.2%  최악 4.2%  손실 0%   ← 진입시점 1개
10년 보유  데이터 기간이 짧아 낼 수 없습니다
```

**원인 두 개.** (a) 실제 버그 — 종료 분기를 정확히 요구해서 거래 없는 분기 하나에 진입시점이
통째로 날아갔습니다. (b) 디자인 — 숫자 네 개를 늘어놓으면 **서로의 간격**이 안 보이는데, 정작
의사결정에 쓰이는 건 간격입니다.

**조치:** 버그 수정(±1분기 허용) + 분포 띠(박스플롯) + 기준선 대비 안전마진.

### ④ "초과수익률이 무슨 뜻인지 모르겠다"

표 머리글에 `초과`라고만 적혀 있었습니다. 무엇 대비 초과인지 알 방법이 없었습니다.

**조치:** 호버 설명 추가.

### ⑤ 호칭 오류

작성자를 잘못 불렀습니다. 도구와 무관하지만, **이 도구는 두 사람의 사적인 재무 결정을 다룹니다.**
톤이 어긋나면 신뢰가 깎입니다.

### 이 다섯 건의 공통 패턴

> **결과는 보여주는데 그 결과에 이르는 경로가 안 보입니다.**

숫자는 다 맞았습니다. 사용자가 막힌 건 전부 "이 숫자가 어디서 왔나 / 무엇 대비인가 /
왜 저건 안 보이나"였습니다. **이게 이 도구의 핵심 디자인 문제라고 봅니다.**

## 6. 우리가 보는 나머지 문제 (작성자 의견, 미검증)

**(가) 배지 인플레이션.** 매트릭스 셀 하나에 배지가 최대 5개, 행 머리글에 2개 더 붙습니다.
`LTV가 막음` `부담 32%` `레버리지 역효과` `보금자리론 밀림` `2종 부적격` — 전부 같은 시각 무게라
무엇부터 봐야 할지 알 수 없습니다. 전체 배지 종류는 19개입니다.

**(나) 경고문이 무뎌짐.** 거의 모든 카드 하단에 주의사항 목록이 있습니다. 원칙 4를 지키려다
**다 중요하다고 말해서 아무것도 중요하지 않게 됐습니다.** 위계가 필요합니다.

**(다) 탐색 구조가 평평함.** 7탭이 동렬인데 실제 성격은 3층입니다 —
입력(1·2·3) / 판정(4·5) / 근거(6·드로어) / 산출(7). 번호는 순서를 암시하지만 실제로는
4번과 5번을 오가며 씁니다.

**(라) 색 의미의 중복.** sky가 "선택됨"이면서 "매수 갈래", emerald가 "좋음"이면서 "적립액",
amber가 "주의"이면서 "하위 25%"입니다.

**(마) 모바일 미대응.** 매트릭스 `min-w-[720px]`, 드로어 `max-w-xl`. 폰에서 못 씁니다.
**다만 이게 실제 문제인지는 확실하지 않습니다** — 지금까지 데스크톱에서만 썼습니다.

**(바) 산출 경로가 둘.** 리포트 탭(인쇄용)과 드로어의 마크다운 다운로드가 따로 놉니다.

## 7. 디자이너에게 묻고 싶은 것

우선순위 순입니다.

1. **결과에서 근거로 내려가는 동선을 어떻게 만들까요.** 지금은 배지 호버(툴팁)에 의존하는데,
   인쇄하면 사라지고 모바일에선 뜨지 않습니다. "3.04억"에서 "왜 3.04억인가"로 가는 길이
   필요합니다. 지금은 셀을 클릭하면 전 상품 계산 내역 드로어가 열리지만, **클릭할 수 있다는 것
   자체가 안 보입니다.**

2. **가정값과 실측값을 어떻게 구분해 보일까요.** 지금은 `실측 아님` / `일부 실측` 배지 하나입니다.
   같은 화면에 실측(전세가율 80.0%)과 자리표시자(투자수익률 6%)가 나란히 있는데 시각적으로
   거의 같습니다. **이 구분이 흐려지면 도구 전체가 거짓말이 됩니다.**

3. **19개 배지에 위계를 어떻게 줄까요.** 줄이는 게 답인지, 묶는 게 답인지, 등급을 나누는 게
   답인지 모르겠습니다.

4. **7탭을 재구성해야 할까요.** 아니면 라벨과 그룹만 손봐도 될까요.

5. **한계·주의 문구를 어떻게 살릴까요.** 지우면 원칙 위반이고, 두면 아무도 안 읽습니다.

6. **분포 띠(박스플롯)가 일반인에게 읽히나요.** ③에서 새로 넣은 요소인데 검증하지 못했습니다.

## 8. 성공 기준

숫자 목표가 아니라 **행동으로 확인할 수 있는 것**으로 적습니다.

- 화면을 처음 보는 사람이 **"이 숫자가 어디서 나왔는지"를 물어보지 않고** 스스로 찾아갈 수 있다.
- **가정값과 실측값을 섞어서 인용하지 않는다.** ("전세가율 80%니까" ✅ / "10년 뒤 3.28억이니까" ❌)
- 매트릭스 셀에서 **무엇부터 읽어야 할지** 눈이 자동으로 간다.
- 인쇄본만 들고 논의 자리에 가도 **호버로만 있던 정보가 빠지지 않는다.**
- 두 사람이 같은 화면을 보며 **서로 다른 것을 가리키지 않는다.**

## 9. 건드리면 안 되는 것

- 점수 통합, 단일 종합 등급
- 부정적 결과(자금 부족·탈락 사유)를 접거나 숨기기
- 가정값을 실측처럼 보이게 하는 표현
- "추천"을 단정적으로 만드는 것 — 목적함수를 바꾸면 답이 바뀐다는 사실이 항상 보여야 합니다
- 외부 리소스 요청 (단일 HTML 제약)
