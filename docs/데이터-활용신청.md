# 희용님이 하셔야 할 것 — 데이터 활용신청

이 저장소의 실측 데이터는 전부 **빌드 타임에 받아 JSON으로 굽습니다.**
정적 단일 HTML이라 런타임에 키를 둘 수 없기 때문입니다.

키는 `.env.local` (gitignore)에 있고 지금 4종이 등록돼 있습니다.
아래 둘은 **API별 활용신청이 따로 필요**하고, 그건 희용님 계정에서만 됩니다.

---

## ✅ 1. 행안부 통계연보 지역별 주민등록인구 → `populationTrend` **완료**

승인 완료. `npm run fetch:population` 으로 받습니다.

**다만 시도 단위입니다.** 창원 성산구와 마산회원구를 가르지 못하고, 같은 권역
시군구는 전부 같은 값을 받습니다. 시군구 단위가 필요하면 별도 자료를 찾아야
합니다 — 지금은 권역 축에서만 씁니다.

<details><summary>당시 기록 (신청 절차)</summary>

### (구) 행안부 주민등록 인구통계 → `populationTrend` 실측

**막힌 지점.** 지금 `MOLIT_API_KEY`(data.go.kr 일반 인증키)로 호출하면 이렇게 돌아옵니다.

```
{"errMsg":"SERVICE_KEY_IS_NOT_REGISTERED_ERROR","returnReasonCode":"30"}
```

data.go.kr 인증키는 계정 단위지만 **활용신청은 API 단위**입니다. 신청이 안 된
API는 같은 키로도 안 열립니다.

**하실 일**

1. <https://www.data.go.kr> 로그인
2. "주민등록 인구통계" 검색 → 행정안전부 제공 오픈API
3. `활용신청` → 활용목적에 "개인 주택 매수 의사결정 도구 (비영리)" 정도로 기재
4. 승인은 보통 즉시~1영업일. 마이페이지 > 오픈API > 개발계정에서 상태 확인

**승인 뒤**

`.env.local` 의 `MOLIT_API_KEY` 를 그대로 씁니다 (같은 계정 = 같은 키).
알려 주시면 수집 스크립트를 붙이겠습니다 — 시군구별 인구 추세를 내서
`populationTrend` 주관 입력 옆에 실측 신호로 놓습니다. UI 자리는 이미 있습니다
(`＋ 물건 · 입지` 탭 > 인구·일자리 추이 > "실측 대기").

**왜 값어치가 있나.** `populationTrend` 는 창원 가중치가 **10** 으로 전체 지표 중
가장 높습니다. 지금 이 축이 순수 주관인데, 창원은 인구 유출이 실제 쟁점입니다.

## ✅ 2. 수선유지비 — **하한까지 실측 완료**

세 API 모두 승인됐고 `npm run fetch:repair` 로 받습니다.

```
단지목록      AptListService4/getSigunguAptList4        시군구 → 단지코드
기본정보      AptBasisInfoServiceV5/getAphusBassInfoV5  세대수·총전용면적
관리비        AptRepairsCostServiceV3/getHsmpMonthFeeInfoV3  월 부과액
```

318개 단지 표본 — 창원 222.5 · 부산 200 · 경기 309.5 원/㎡/월.

**다만 장기수선충당금뿐입니다.** 공용부 대규모 수선 적립금이라 세대 내부
수선(도배·싱크대·보일러)이 빠져 있어 **수선유지비의 하한**입니다. 그래서
가정 0.5% 를 덮어쓰지 않고 "가정이 하한의 8배" 라고만 화면에 적습니다.

<details><summary>당시 기록</summary>

### (구) 수선유지비 — 한 번 더 신청이 필요합니다

`국토교통부_공동주택관리비(장기수선충당금)정보서비스` 는 **승인 완료**이고
호출도 정상입니다 (`resultCode 00`).

**막힌 지점.** 이 API 는 입력으로 **단지코드(`kaptCode`)** 를 받습니다. 창원·부산·
경기 단지를 훑으려면 그 코드 목록이 필요한데, 목록을 주는 API 가 따로입니다.

**하실 일 — 이것 하나만**

> `국토교통부_공동주택 단지 목록제공 서비스` → [활용신청]
> <https://www.data.go.kr/data/15057332/openapi.do>

승인되면 `getSigunguAptList4` 로 시군구별 단지코드를 받고,
`getHsmpAccumulationTariffInfoV3` 로 단지별 장기수선충당금 적립요율을 받아
지역 중위값을 룰셋에 굽습니다.

<details><summary>당시 기록</summary>

### (구) 공동주택관리정보시스템(K-apt) → 수선유지비 0.5% 실측

**막힌 지점.** 룰셋의 `maintenanceRate: 0.005` 는 근거가 통상값뿐입니다.
매수·청약 갈래만 부담하는 값이라, 0.5%p만 움직여도 10년 보유 기준으로
주택가격의 5%가 오갑니다.

**하실 일**

1. <https://www.data.go.kr> 에서 "공동주택 관리비" 또는 "K-apt" 검색
2. 국토교통부/한국부동산원 제공 관리비 상세 API 활용신청
3. 특히 **장기수선충당금** 항목이 있는 API를 고르세요 — 일반 관리비(청소·경비)는
   임차인도 내므로 소유자 부담인 수선유지비와 다릅니다

**승인 뒤**

단지별 장기수선충당금(원/㎡)을 받아 주택가격 대비 비율로 환산하고,
지역별 중위값을 룰셋에 굽습니다. 지금 `tenure.assumptionDefaults.basis.maintenanceRate`
에 적어 둔 `wouldSettle` 이 바로 이것입니다.

## ⏳ 3. 청약홈 — 공고 자동 수집 + 경쟁률

공고 분석 화면을 위해 필요합니다. 지금은 분양가·평형·입주예정을 손으로
넣어야 하는데, 이 두 API 가 붙으면 **목록에서 고르기만** 하면 됩니다.

> **분양정보** <https://www.data.go.kr/data/15098547/openapi.do>
> **경쟁률**   <https://www.data.go.kr/data/15098905/openapi.do>

**명세는 이미 확인했습니다** (로그인 없이 공개).

```
BASE https://api.odcloud.kr/api/ApplyhomeInfoDetailSvc/v1
  getAPTLttotPblancDetail   주택명 · 공급위치 · 총세대 · 모집공고일 · 접수일정
                            · 당첨자발표 · 계약일 · 입주예정월(MVN_PREARNGE_YM)
  getAPTLttotPblancMdl      주택형별 전용면적 · 공급세대 · 분양가(LTTOT_TOP_AMOUNT)
                            · 특별공급 유형별 세대수(생애최초·신혼·다자녀…)
```

`SubscriptionPlan` 의 거의 모든 필드가 자동으로 채워집니다. 손입력으로 남는
것은 **중도금 조건(이자후불 여부·금리)과 전매제한** 뿐입니다 — 이 둘은 단지
공고문에만 있습니다.

승인되면 알려 주세요. 수집 스크립트를 붙이겠습니다.

## ⚠️ 함정 — 인증키 이중 인코딩

`.env.local` 의 `MOLIT_API_KEY` 는 **Encoding 키**(`%` 포함)입니다.
URL 에 **그대로** 붙여야 합니다. 한 번 더 인코딩하면 `%2B` 가 `%252B` 가 되어
이렇게 돌아옵니다.

```
SERVICE_KEY_IS_NOT_REGISTERED_ERROR / 등록되지 않은 서비스키
```

문구는 "키가 미등록" 이라고 말하지만 실제로는 인코딩 사고입니다.
**이미 되던 API(매매 실거래가)로 먼저 대조**하면 30초에 가려집니다 —
그것까지 같은 오류를 내면 키·인코딩 문제이고, 그것만 되면 신청 문제입니다.

## 실측이 불가능하다고 확인된 것

키를 더 받아도 안 되는 것들입니다. 추측이 아니라 **API를 직접 두드려 확인**했습니다.

| 값 | 확인 결과 |
|---|---|
| 코스피 총수익지수(TR) | KRX 지수 API 가 주는 코스피 계열 51개가 전부 가격지수 |
| S&P500 배당수익률 | FRED 검색 결과 1969년에 끝난 NYSE 계열뿐 |
| S&P500·나스닥100 총수익지수 | FRED 에 `SP500TR`·`WILL5000IND` 등 없음 (직접 조회 실패 확인) |

그래서 가격지수 CAGR 에 배당을 더한 근사를 쓰고 화면에 그렇게 적습니다.
**코스피 배당은 ECOS 에 있어서 실측으로 바꿨습니다** (20년 평균 1.60%).
미국 지수 배당만 가정으로 남습니다 — 같은 "실측+가정" 이라도 근거 수준이
다르다는 것을 화면 문구로 갈라 뒀습니다.
