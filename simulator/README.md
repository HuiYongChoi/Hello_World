# 주택 매수 의사결정 시뮬레이터

대출 시나리오 계산과 물건 입지 평가를 **한 화면에서 결합**하여, 현행 정책 하 최적 조달안을 도출하는 도구입니다.

## 왜 이 도구인가

기존 부동산 계산기는 "대출"과 "물건"을 따로 봅니다. 하지만 두 축은 얽혀 있습니다.

```
경기권  = 수도권   = LTV 70%  (생애최초 우대 무효)
창원·부산 = 비수도권 = LTV 80%  (생애최초 우대 유효)
```

**지역 선택이 곧 대출 조건 선택**입니다. 이 커플링을 UI에서 명시적으로 드러내는 것이 이 도구의 존재 이유입니다.

핵심 산출물은 단일 점수가 아니라 *"이 물건을 이 시나리오로 사면 매달 얼마를 내고, 현금이 얼마 필요하며, 입지 점수는 몇 점인가"* 의 **3축 비교표**입니다.

## 실행

```bash
npm install
npm run dev      # 개발 서버
npm run build    # 프로덕션 빌드 → dist/
npm run preview  # 빌드 결과 미리보기
npm test         # 계산 엔진 단위 테스트
```

입력값은 브라우저 localStorage에 자동 저장됩니다. 서버로 전송되는 데이터는 없습니다.

## 배포

CSS·JS를 문서 안에 전부 인라인해 **외부 요청이 0건인 단일 HTML**을 만듭니다. 오프라인에서도, 파일을 직접 열어도 그대로 동작합니다.

```bash
npm run standalone      # dist/standalone.html — 본문 조각 (호스트가 골격을 씌우는 환경용)
npm run deploy:realty   # 완전한 HTML 문서 → 저장소 루트 realty/index.html
```

`deploy:realty`가 만든 파일이 GitHub Pages의 `/realty/` 경로로 서비스됩니다. 코드를 고친 뒤에는 이 명령을 다시 돌리고 커밋·푸시하면 반영됩니다.

저장소 루트의 `.nojekyll`은 Pages가 Jekyll 처리를 건너뛰게 합니다.

### 자체 서버(AWS/Bitnami)로 배포

```bash
cp .env.deploy.example .env.deploy   # 서버 주소·SSH 키 경로 채우기
./scripts/deploy-aws.sh
```

빌드 후 `realty/index.html`을 서버 웹 루트 하위 경로로 올립니다. 단일 파일에 외부 요청이 없어서 **어떤 경로에 두어도 그대로 동작**합니다 — 재빌드 없이 `/hyrealty/`든 `/realty/`든 같은 파일을 씁니다.

접속 정보는 스크립트에 넣지 않고 `.env.deploy`로 분리했습니다. 이 저장소는 공개라 서버 주소와 키 경로가 커밋되면 그대로 노출됩니다.

> **API 키는 이 사이트에 넣을 수 없습니다.** 정적 단일 HTML이라 문서에 담긴 값은 누구나 읽습니다. 외부 데이터가 필요해지면 빌드 타임에 받아 JSON으로 굽거나(권장), 서버 측 프록시를 두어야 합니다.

## 화면 구성

| 단계 | 화면 | 역할 |
|---|---|---|
| 1 | 가구 프로필 | 소득·자산·생애최초·혼인상태 입력 |
| 2 | 시나리오 | 혼인시점 × 명의 4종의 파생 상태 확인, 목적함수 선택 |
| 3 | 물건 · 입지 | 물건 등록 + 22개 지표 스코어링 + 레이더 차트 |
| 4 | 비교 매트릭스 | **핵심 화면** — 물건 × 시나리오 셀별 최적 상품·월납·필요현금 |
| 5 | 리포트 | 인쇄/PDF용 종합 요약 |

지역군은 **물건에 귀속**되므로 시나리오 축은 혼인시점 × 명의 4종이며, 최종 조합 수는 `4 × 물건 수`입니다.

## 아키텍처

```
src/
  rules/2026-08.json   ← 모든 정책 수치. 코드엔 로직만.
  engine/              ← 순수 TS. UI 의존성 없음. 단위테스트 대상.
    rules.ts           룰셋 로더 + 지역/규제지역 판정
    finance.ts         원리금균등 상환 계산 (PMT / PV)
    scenario.ts        프로필 × 시나리오축 → 파생 상태
    costs.ts           취득세·중개보수·부대비용
    loan.ts            한도 계산 파이프라인 + 상품 랭킹
    scoring.ts         입지 지표 정규화 + 지역별 가중치 프리셋
    matrix.ts          매트릭스 조립 + 3축 산점도 데이터
  state/store.tsx      React 상태 + localStorage 영속화
  pages/               화면
```

**계산 엔진은 UI에서 분리되어 있습니다.** 정책이 바뀔 때마다 UI를 건드려야 한다면 유지보수가 불가능해집니다.

## 한도 계산 파이프라인

```
STEP 1  자격 게이트   소득·자산·주택가격·면적·생애최초·연령·시행일
STEP 2  LTV 한도      수도권 여부 → 규제지역 여부 순으로 적용
STEP 3  상품 캡       단독세대주 축소 한도, 수도권 절대상한
STEP 4  상환능력 한도  DSR 면제 상품은 DTI, 은행 상품은 DSR + 스트레스 금리
STEP 5  최종          min(위 네 값) + binding constraint 판별
```

`bindingConstraint` 노출이 UX의 핵심입니다. "3.2억"만 보여주면 사용자는 왜 그 숫자인지 모릅니다. **"LTV가 막았음 / DSR이 막았음 / 상품 캡이 막았음"**을 배지로 표시하면 다음 행동(소득 늘리기 vs 지역 바꾸기 vs 물건 낮추기)이 바로 나옵니다. 조언 문구는 물건 맥락을 반영합니다 — 이미 비수도권 80%를 받고 있는 물건에는 "비수도권으로 바꾸라"고 하지 않습니다.

## 레버리지 방향 — LTV 80%가 항상 유리하지는 않습니다

```
r_equity ≈ r_asset + (L/E) × (r_asset − i)
                      ↑배율      ↑스프레드
```

배율은 곱셈으로, 금리는 스프레드 안의 한 항으로 들어갑니다. 따라서 **스프레드의 부호가 1차 관문**입니다.

| 가격상승률 | 스프레드 | LTV 70% (배율 2.33) | LTV 80% (배율 4.0) |
|---|---|---|---|
| 1% | 음수 | 손실 | **더 큰 손실** |
| 8% | 양수 | 이익 | **더 큰 이익** |

가격상승률이 대출금리를 밑도는 구간에서는 비수도권 LTV 80% 우대가 **오히려 독**입니다. 매트릭스 상단의 가격상승률 슬라이더를 움직이면 셀 배지가 `레버 4.0배` ↔ `레버리지 역효과`로 뒤집히고, 셀을 열면 스프레드 분해가 나옵니다.

이 계산은 방향을 보기 위한 1차 근사입니다. 원금상환·보유세·거래비용·양도세를 제외했으므로 수익률 예측치가 아닙니다 — UI에도 그렇게 명시했습니다.

## 정책 개정 시 대응

이 도메인의 최대 리스크는 **규정 자체가 자주 바뀐다**는 점입니다.

1. `src/rules/2026-08.json`의 수치만 수정하거나, 새 파일을 만들고 `engine/rules.ts`의 import를 교체합니다.
2. 룰셋에는 `version`, `effectiveFrom`, `sunset` 필드가 필수입니다.
3. 화면 하단에 **적용 규정 기준일**이 상시 표시됩니다.
4. 시행 예정 제도는 `effective_from` 필드로 관리되며, 매수 예정일이 시행일 이전이면 자동으로 제외되고 경고가 붙습니다 (예: 보금자리론 신혼 소득요건 완화 2026-10-01).
5. `npm test`로 회귀를 확인합니다.

## 설계상 원칙

- **점수를 하나로 합치지 않습니다.** 입지 88점 + 대출 적합 60점 = 74점은 아무 의미가 없습니다. 사용자가 축별로 보고 스스로 판단해야 합니다.
- **부정적 결과를 숨기지 않습니다.** "자금 부족"이 나오는 조합, 자격 미달 상품의 탈락 사유가 모두 그대로 표시됩니다.
- **가중치를 사용자가 직접 조절**할 수 있습니다. 지역 프리셋은 출발점이지 정답이 아닙니다.
- **입지 점수는 주관적 입력의 가중합**입니다. 객관적 시세 예측이 아니며 UI에 명시되어 있습니다.
- **목적함수 주의**: 월납·이자 최소화는 덜 빌리는 쪽을 유리하게 만듭니다. 월납과 필요현금을 반드시 함께 읽어야 합니다.
